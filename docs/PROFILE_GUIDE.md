# Как поддерживать GitHub-профиль

Профиль хранится в публичном репозитории [yergaliuly/yergaliuly](https://github.com/yergaliuly/yergaliuly).
GitHub показывает его `README.md` на странице [yergaliuly](https://github.com/yergaliuly).
Основная ветка репозитория — `main`. Локальные правки появятся в профиле только после отправки на GitHub.

## Что здесь находится

| Файл | Для чего нужен |
| --- | --- |
| `README.md` | Английский текст и оформление публичного профиля. |
| `assets/marin.gif` | Выбранная анимация Marin. |
| `AGENTS.md` | Правила для помощника, который меняет профиль. |
| `docs/PROFILE_GUIDE.md` | Это руководство по работе с профилем. |
| `.gitignore` | Список локальных файлов, которые Git не должен добавлять автоматически. |

Папка `assets` содержит изображения и другие материалы оформления.
Исходные видео, запасные копии GIF, снимки предпросмотра и данные входа хранятся отдельно от репозитория.
`.gitignore` не скрывает файлы, которые уже попали в историю Git.

## Несколько слов о Git

- **Репозиторий** — папка проекта вместе с историей изменений.
- **Markdown** — простой формат текста: `#` задаёт заголовок, `**текст**` — выделение.
- **Ветка** — отдельная линия изменений; здесь работа идёт в `main`.
- **Remote** — адрес удалённого репозитория; имя `origin` обозначает репозиторий на GitHub.
- **Commit** — сохранённый в локальной истории набор изменений с пояснением.
- **Push** — отправка локальных коммитов в удалённый репозиторий.

Сохранение файла в редакторе, создание коммита и отправка на GitHub — три разных действия.

## Как менять текст

1. Открой папку репозитория в VS Code и выбери `README.md`.
2. Измени нужный абзац и сохрани файл. Публичный текст оставляй на английском.
3. Нажми `Ctrl+Shift+V`, чтобы открыть предпросмотр Markdown.
4. Проверь читаемость, ссылки и расположение изображения.

В `About` добавляй только подтверждённые сведения о себе.
Список `Tech` сейчас содержит Java, Spring Boot, PostgreSQL и Git.
Сохраняй спокойное оформление Midnight × Marin: короткие разделы, свободное пространство и немного акцентов.
GitHub поддерживает Markdown и часть HTML; произвольные CSS и скрипты для этого README не нужны.

## Как обращаться с GIF

Текущий `assets/marin.gif` сохраняется без изменения его содержимого.
Замена, обрезка, сжатие или повторная генерация возможны только по желанию владельца.
Перед согласованной заменой сохрани оригинал отдельно, за пределами репозитория.

В `README.md` используется относительный путь с точным регистром букв:

```html
<img src="assets/marin.gif" alt="Marin Kitagawa animation in a dark room with manga artwork and muted pink accents" width="310">
```

Чтобы изменить отображаемую ширину, поменяй только число в `width`: например, `width="300"` или `width="320"`.
Для текущей композиции выбрано `width="310"`. Не задавай `height`: высота должна следовать пропорциям GIF.
Эта настройка меняет размер на странице, но не содержимое и не вес исходного файла.
Путь считается от `README.md`; название `marin.gif` и папка `assets` должны совпадать с ним.
Если содержание изображения изменится, обнови и описание в `alt`.

Если изображение не отображается:

1. Проверь, что `assets/marin.gif` существует рядом с корневым `README.md` в структуре репозитория.
2. Сравни путь и регистр букв с `src`: на GitHub `Marin.gif` и `marin.gif` — разные имена.
3. Открой ветку `main` на GitHub и убедись, что GIF вошла в коммит и была отправлена вместе с README.
4. Открой сам файл GIF в репозитории. Если он тоже не загружается, проверь соединение и повтори загрузку страницы.
5. Если новая версия видна в файлах, но не в профиле, обнови страницу после небольшой паузы: изображение могло остаться в кэше.

## Как добавить проект

В разделе `Projects` уже есть [StudyMate](https://github.com/yergaliuly/StudyMate).
Для нового проекта сначала открой его настоящий репозиторий и прочитай актуальный README.
Убедись, что ссылка доступна предполагаемому читателю, затем скопируй точный адрес в профиль.
Добавь название со ссылкой и одно короткое английское предложение о реализованных возможностях.
Не подставляй вымышленные адреса, планы вместо готовых функций или неподтверждённые достижения.

## Проверка и публикация

Команды ниже выполняются в терминале PowerShell из папки этого репозитория.
Сначала проверь текущую ветку, адрес назначения и изменения:

```powershell
git status --short --branch
git remote -v
git diff --stat
git diff
git fetch origin
git log --oneline --left-right HEAD...origin/main
```

Назначение должно быть `yergaliuly/yergaliuly`, рабочая ветка — `main`.
`fetch` получает сведения о GitHub, не публикуя локальные правки.
В последнем выводе `<` означает локальные коммиты, а `>` — коммиты только на GitHub.
Если есть `>`, сначала согласуй изменения с `origin/main`, сохранив свою работу и разрешив конфликты.
Если история разошлась, разберись с ней до отправки; не используй принудительную отправку или разрушительный сброс.

Добавь в будущий коммит только проверенные файлы:

```powershell
git add -- README.md assets/marin.gif AGENTS.md docs/PROFILE_GUIDE.md .gitignore
git diff --cached --stat
git diff --cached
git status --short
```

`git diff` показывает изменения ещё не добавленные в коммит, а `--cached` — уже подготовленные.
Новые файлы сначала видны в `git status`; после `git add` их содержимое попадёт в подготовленный diff.
GIF — двоичный файл: текстовый diff не покажет кадры. Проверь его визуально и посмотри `--stat`.
Убедись, что в коммит не попали исходники, локальные копии, личные пути или секреты.

Сохрани проверенные изменения в локальной истории:

```powershell
git commit -m "Update GitHub profile"
```

Перед публикацией покажи владельцу точный список файлов, назначение `yergaliuly/yergaliuly`, ветку `main`
и публичную видимость репозитория. Получи подтверждение на отправку.
Если сохранено несколько учётных записей GitHub, проверь, что для отправки выбрана `yergaliuly`.
Список сохранённых аккаунтов можно посмотреть командой `git credential-manager github list`.
Этот список показывает доступные аккаунты, но не подтверждает, какой будет использован для отправки.
Настройки автора коммита `user.name` и `user.email` тоже не подтверждают аккаунт для входа.
Для этого HTTPS-репозитория можно выбрать нужное имя только на время одной команды:

```powershell
git -c credential.https://github.com.username=yergaliuly push origin main
```

Если появится вход в GitHub, проверь аккаунт `yergaliuly` перед продолжением.
Не меняй глобальные настройки Git и не используй `--force`.
Если push отклонён из-за новых коммитов на GitHub, повтори `fetch`, сравни историю и согласуй изменения.

После успешной отправки открой настоящий профиль и README на GitHub, проверь ветку по умолчанию `main`.
Проверь ссылки, анимацию, ширину и читаемость в светлой и тёмной темах, а также на узком экране.
Предпросмотр VS Code помогает при редактировании, но окончательный вид проверяется на GitHub.
