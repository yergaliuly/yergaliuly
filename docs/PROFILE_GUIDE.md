## Текущее оформление

контакт, четыре проекта, основной стек и ссылки на обучение.

Используются нативные шрифты и тема GitHub. Стек по уточнённому запросу владельца
показан небольшими бейджами с рамкой, названием и логотипом там, где он есть.
Баннеры, анимация, большие карточки, JSON-биография и декоративная навигация не нужны.
Основной текст читается сверху вниз и естественно переносится на телефоне.

## Проверка изменений

1. Прочитай README целиком: короткие абзацы, понятные ссылки, конкретные описания.
2. Проверь относительные пути и регистр. Путь в README отсчитывается от корня,
   а в `docs/STACK.md` — от `docs/`.
3. Проверь разметку через GitHub Markdown API или обычный предпросмотр редактора.
   Приблизительный локальный HTML не считается проверкой настоящего профиля.
4. Проверь diff, отсутствие приватных путей, токенов и временных материалов.
5. После разрешённой публикации проверь настоящий профиль на 1280 и 390 px:
   перенос текста и ссылок, отсутствие горизонтальной прокрутки, открытие STACK и каталога.
6. Кратко обнови статус проекта с результатом и ограничениями проверки.

Не запускай сайт или сервер ради README. Для этой версии не нужны сборщик,
генератор графики, workflow статистики или новые зависимости.
Старую графику и её лицензии сохраняй; не удаляй историю ради нового оформления.

## Сохранение и публикация

Сохранение, локальный коммит и публикация — разные действия.
Перед изменениями проверь `git status`, затем `git diff` и `git diff --check`.
Добавляй явные пути файлов, например:

```powershell
git add -- README.md docs/STACK.md docs/PROFILE_GUIDE.md
git diff --cached
```

Публикация должна соответствовать запросу владельца и разрешённому назначению.
Используй уже данное разрешение в пределах его области; не проси то же разрешение повторно.
Перед отправкой назови конкретный набор файлов, аккаунт `yergaliuly`, public-репозиторий
`yergaliuly/yergaliuly` и `main`. Для нового назначения, изменения видимости или настроек
нужно отдельное согласование. Если разрешения на действие нет, покажи готовый пакет до вопроса.

В Credential Manager может быть несколько аккаунтов. Проверь реальный аккаунт через
официальный API, не печатай пароль или токен. Для отправки можно выбрать пользователя
только для этой команды, не меняя глобальные настройки:

```powershell
git -c credential.https://github.com.username=yergaliuly push origin main
```

Перед отправкой выполни fetch и сравни историю. Используй обычный push и fast-forward,
если история позволяет. При новых чужих коммитах разберись с ними; не используй force push.
После отправки проверь default branch и настоящий профиль.

## Отдельные настройки аккаунта

Аватар, display name, bio и pinned repositories не меняются через README.
Применение новых значений согласовывай отдельно. Не подставляй чужую фотографию или
сведения из референса. Прежний `assets/avatar.png` относится к теме Саске.

Для будущего согласования bio подходит:
`Java Backend Developer. AITU student. Building with KDvibers.`

Тема GitHub — предпочтение конкретного посетителя; README следует его теме.
В Popular repositories → Customize your pins можно отдельно закрепить доступные проекты
FocusDuo, HackAtlas, forte-cash-audit и StudyMate. Список Projects в README сам их не закрепляет.
