# Как поддерживать GitHub-профиль

Это руководство для публичного профильного репозитория [yergaliuly/yergaliuly](https://github.com/yergaliuly/yergaliuly).
GitHub показывает непустой корневой `README.md` из ветки по умолчанию на странице [yergaliuly](https://github.com/yergaliuly).
Рабочая ветка — `main`. Сохранение файлов, локальный коммит и публикация — разные действия.

`.gitignore` не удаляет из истории то, что уже было закоммичено.

## Как менять текст

**README** — главный текстовый файл репозитория. **Markdown** — формат его разметки: `#` задаёт заголовок, `**текст**` — выделение.
Открой `README.md` в VS Code, измени нужный абзац и сохрани файл. Публичный текст оставляй на английском.
Приветствие — `Hi, I'm yergaliuly`, подпись — `Java · Backend Development`.
В About Me указывай только подтверждённые сведения о себе; основной стек — Java, Spring Boot, PostgreSQL и Git.

Сохраняй короткие абзацы и нормальную иерархию заголовков.
Не переноси из художественного макета специальность, достижения, подписчиков, звёзды и другие неподтверждённые данные.
Основной текст должен оставаться текстом, а не частью общей картинки.
В README используются Markdown и поддерживаемый GitHub HTML; произвольные CSS, скрипты и iframe сюда не добавляй.

## Картинки, размеры и пути

**Относительный путь** отсчитывается от файла, в котором он записан. В корневом README это, например, `assets/banner.png`:

```html
<img src="assets/banner.png" alt="Sasuke Uchiha beneath a moonlit sky" width="736">
```

`src` указывает файл, `alt` описывает содержание, `width` задаёт отображаемую ширину в пикселях.
Меняй только ширину; без фиксированной высоты сохраняются пропорции. Это не меняет исходный PNG и не улучшает его разрешение.
Баннер рассчитан на ширину до 736 px, About Me — около 260–300 px, `footer-art.png` — до 352 px.
Не увеличивай небольшие исходники ради заполнения всей страницы. Меняя картинку, обнови `alt` по её содержимому.

Обтекание `align="right"` позволяет разместить About Me рядом с текстом, но требует проверки в узком окне.
Если текст сжимается в неудобную колонку, убери `align="right"` и поставь изображение отдельным абзацем после текста.
Карточки технологий отображаются шириной 104 px; содержательный `alt` должен сохранять название технологии.
При изменении сторонних иконок сохраняй сведения об источниках и лицензии из `assets/icons/`.
Для завершения используй один нижний рисунок. Предпочтительный вариант — `footer-art.png` и обычный текст `Always learning. Always building.`

Если картинка сломалась:

1. Проверь наличие файла и точный регистр: `banner.png` и `Banner.png` на GitHub различаются.
2. Сверь `src` с расположением файла. Не используй локальные абсолютные пути или адреса `file://`.
3. Убедись, что изображение вошло в коммит вместе с README и отправлено в `main`.
4. Открой сам файл в репозитории на GitHub; проверь, загружается ли он.
5. Если файл обновился, а профиль ещё показывает старую версию, обнови страницу после небольшой паузы: возможен кэш.

## Как добавить проект

Раздел Featured Project ведёт на настоящий [StudyMate](https://github.com/yergaliuly/StudyMate).
Перед изменением его описания прочитай актуальный README проекта и пиши только о реализованных возможностях.
Для нового проекта добавь название, точную доступную ссылку и короткое английское описание.
Не используй планы как готовые функции, не добавляй вымышленные адреса, показатели и контакты.
Декоративное изображение нельзя называть скриншотом интерфейса. Сам репозиторий StudyMate для оформления профиля менять не нужно.

## Предпросмотр

В VS Code нажми `Ctrl+Shift+V`, чтобы увидеть Markdown, затем проверь текст, ссылки и загрузку файлов.
Локальный предпросмотр полезен для редактирования, но GitHub применяет собственные стили и очистку HTML.
Локальный HTML и художественный макет не подтверждают фактический вид опубликованного профиля.

Проверяй на настоящем GitHub широкий экран и узкое окно около 390 px, светлую и тёмную тему.
Обрати внимание на About Me, перенос карточек, ширину баннера и отсутствие горизонтальной прокрутки.
Если проверка недоступна, запиши ограничение и повтори её после публикации; не называй её выполненной заранее.
README не управляет левой панелью, Achievements и настройками темы посетителя. Композиция адаптирует макет к реальному GitHub.

## Сохранение и публикация

**Репозиторий** — папка проекта с историей. **Ветка** — отдельная линия этой истории, здесь `main`.
**Remote** — адрес удалённой копии; `origin` — её короткое имя. **Commit** сохраняет проверенный набор правок локально.
**Push** отправляет коммиты на GitHub. **Pull request** предлагает изменения для объединения в целевую ветку; само его создание ещё не публикует профиль.
Следующие команды выполняются в PowerShell из папки профильного репозитория, небольшими этапами.

`git status` показывает ветку и состояние файлов; `remote -v` — адреса чтения и отправки. Они ничего не публикуют:

```powershell
git status --short --branch
git remote -v
```

Проверь ветку `main` и назначение `yergaliuly/yergaliuly`. `git diff --stat` даёт сводку, `git diff` — правки, ещё не подготовленные к коммиту:

```powershell
git diff --stat
git diff
```

`fetch` получает сведения с GitHub, не изменяя рабочие файлы. Сравни локальную историю с удалённой:

```powershell
git fetch origin
git log --oneline --left-right HEAD...origin/main
```

`<` обозначает коммиты только локально, `>` — только на GitHub. При наличии `>` сначала сохрани свою работу и согласуй истории.
Не применяй `reset --hard`, принудительную отправку или автоматическое разрешение конфликтов поверх чужих изменений.

`git add --` подготавливает только явно перечисленные пути; `--` отделяет их от параметров команды.
Для обычного изменения текста достаточно примера ниже. Если меняешь рисунок, добавь его точный путь отдельной командой `git add -- assets/about.png`.
Не добавляй весь каталог автоматически и не включай чужие правки:

```powershell
git add -- README.md docs/PROFILE_GUIDE.md
git diff --cached --stat
git diff --cached
git status --short
```

`--cached` показывает будущий коммит. Новые файлы появляются в этом diff после `git add`; PNG проверяй также визуально.
Убедись, что архив, макет, снимки экрана, локальные пути и секреты не попали в набор. Затем создай коммит; `-m` задаёт его пояснение:

```powershell
git commit -m "Update GitHub profile"
```

Перед отправкой покажи владельцу точный набор файлов, содержимое коммита, результаты проверок и ограничения.
Назови remote, аккаунт `yergaliuly`, публичный репозиторий `yergaliuly/yergaliuly`, ветку `main` и способ доставки; получи подтверждение на этот пакет.
Если видимость репозитория изменилась на private, не меняй её автоматически: публичной может стать вся история.

Git Credential Manager может хранить несколько аккаунтов. Команда ниже показывает сохранённые имена, но не доказывает, какое выберет отправка:

```powershell
git credential-manager github list
```

Настройки автора коммита `user.name` и `user.email` также не подтверждают аккаунт входа.
После подтверждения публикации выбери `yergaliuly` для одной команды HTTPS-отправки, не меняя глобальную конфигурацию:

```powershell
git -c credential.https://github.com.username=yergaliuly push origin main
```

Если потребуется вход, используй штатное окно авторизации и проверь аккаунт `yergaliuly`; не передавай токены или пароль в чат.
Если аккаунт другой — остановись до отправки. При отклонении push из-за новых коммитов снова выполни fetch и сравни историю; не используй `--force`.
После успешной отправки открой профиль и корневой README на GitHub, проверь ветку по умолчанию `main`, картинки, ссылки и обе ширины.

## Отдельные настройки аккаунта

Эти действия не выполняются изменением README. Помощнику нужно отдельное подтверждение перед применением настроек.
Выполняй их после входа именно в `yergaliuly`; остальные поля не копируй из макета.

### Аватар

1. Нажми свой аватар справа сверху → **Settings**.
2. В **Public profile**, блок **Profile Picture**, выбери **Edit → Upload a photo…**.
3. Выбери подготовленный `assets/avatar.png`, затем **Upload**.
4. Проверь предложенное GitHub кадрирование и нажми **Set new profile picture**.

Файл имеет размер 176 × 176 px; его копирование в `assets` само по себе не меняет аватар аккаунта.
Шаги: [GitHub Docs — изменение аватара](https://docs.github.com/en/account-and-profile/tutorials/personalize-your-profile#changing-your-profile-picture).

### Bio

Открой **Settings → Public profile**, вставь в **Bio** следующий текст и нажми **Update profile**:

```text
Java & backend development · AITU student · Learning by building.
```

Не меняй вместе с bio username, pronouns, местоположение или компанию по данным с картинки.
Шаги: [GitHub Docs — добавление bio](https://docs.github.com/en/account-and-profile/tutorials/personalize-your-profile#adding-a-bio-to-your-profile).

### Тёмная тема

Открой **Settings → Appearance**. В **Theme mode** выбери **Single theme**, затем нужную тёмную тему из предложенных вариантов.
Для следования системе вместо этого выбери соответствующий режим и дневную/ночную темы.
Это настройка твоего отображения GitHub: посетители сохраняют собственную тему, а фон картинок остаётся частью файлов.
Шаги: [GitHub Docs — настройки темы](https://docs.github.com/en/get-started/accessibility/managing-your-theme-settings).

### Закрепить StudyMate

1. Нажми аватар справа сверху → **Your profile**.
2. У раздела **Popular repositories** или **Pinned** нажми **Customize your pins**.
3. Найди `StudyMate` через **Filter repositories and gists**, отметь нужный репозиторий `yergaliuly/StudyMate`.
4. Проверь остальные выбранные элементы и нажми **Save pins**. Всего можно закрепить до шести репозиториев и gist.

Это отдельная карточка GitHub; ссылка в Featured Project не закрепляет репозиторий автоматически.
Шаги: [GitHub Docs — закрепление проектов](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile).
